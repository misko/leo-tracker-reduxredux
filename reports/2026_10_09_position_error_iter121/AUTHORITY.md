# Conditional replay authority and admission gaps

The existing `TrackingInput` contract exposes session, radio ID, stream generation, counters, UTC timing authority and capture start/end. These identify acquisition and counter continuity; **none attests receiver immobility across captures**. The reviewed mint/deployment descriptions and iteration109 audit likewise provide no independent movement log. Therefore this experiment is conditional-stationary retrospective only. Hardware reset metadata must not be mistaken for movement or immobility evidence.

Iteration107 terminal receipts store elapsed costs, not a authoritative wall-clock result-availability timestamp. Filesystem modification time is not an immutable online receipt. Order is therefore frozen capture-start UTC then inventory label; this is a causal-in-capture-order replay, not real-time latency performance. A single hypothetical stationary episode spans all193 members, with no outcome-selected reset. An additional cold-start-per-dataset comparator has predetermined reset groups DS16/DS17/DS18/newer; dataset boundaries are explicitly artificial reporting resets, not proven hardware/installation events. No clock coefficients are transferred.

The published `../2026_10_09_position_error_iter107/FULL193_COMPLETE_SNAPSHOT.json` (commit580596525) and107protocol hashes are preparation inputs. The completed snapshot accounts for all193 terminal baseline/candidate pairs. Its position-error fields are evaluation-only and must not enter the endpoint exporter/fusion. A separate inference-position snapshot must bind every saved baseline/candidate phase receipt and sources needed to translate each ordinary local vector into geographical coordinates, then obtain parent review before any accuracy calculation. Earlier snapshot102 is superseded for this preparation.

Minimal extraction uses the existing107 reporter's `phase_receipts` for hash/protocol/member admission and `evaluation_document` public authority port for the already terminal member. Copy only `configuration.prior` from that document; apply existing `regional_position_score.coordinates` to each already selected operational fit's first two vector coordinates. Never call `evaluate_fit` during export because it reads reference coordinates. Stage geographic endpoints, capture timestamps, arm/phase identities, qualification and source hashes in an inference-only file, excluding reference/error fields. The original selected operation is retained; fusion does not rescore or choose regions. Later truth evaluation is a separate read/use of the same bound document after the policy/snapshot is reviewed. No raw recording or native model input is needed.

The pure `causal.py` currently accepts only declared membership/order/reset groups and ordinary geographical endpoint fixes. It has no reference/errors, qualification heuristics, optimizer, native loader, numerical covariance or actual endpoint extraction. Inputs require a fixed chart from each arm's first qualified fix; coordinate median is chart-dependent. Three synthetic tests demonstrate prefix causality, arm separation, outages/resets/invalid membership, dateline roundtrip and the non-invariance of coordinate median to chart rotation. No actual position accuracy has been evaluated in iteration121.
