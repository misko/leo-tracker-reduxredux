## Inference and location

The receiver may use the waveform definition, capture metadata and causal signal history. The regional solver may use the operator's search area and orbit information available at capture. Never use evaluation coordinates, recording names, station IDs, a site's observed satellite list or roof-derived frequency or direction masks to choose candidates, thresholds or stopping rules. A cache involving geometry must bind the region, epoch, orbit data and other inputs on which its contents depend. Reordering catalog IDs or moving a region must never retrieve another region's derived geometry.

Treat all previously published regional trials as development regressions. The two published simulated sites include offers containing and omitting the receiver. The previous ALGO08 regional test produced four fixes on the boundaries of four incorrect offers. Record false fixes and displacement explicitly. Agreement with a false fix demonstrates compatibility only. Small coordinate perturbations of a single capture cannot validate physical relocation. ## Escalation and qualification

1. Start with small saved waveform slices and saved solver inputs. Compare independent lanes, weak second carriers, signed CFO, alias boundaries, changed ownership, both calibration arms, and multiple regional frames. Profile before enlarging the panel. Serialize benchmarks with a shared file lock, one pinned CPU, one numerical thread and low scheduling and I/O priority.
2. For a candidate with measured removable cost, use the nested 4- and 16-recording prefixes of the frozen DS30 order. Previously published roof results are development data. Alternate build order and use independent, initially empty output roots. Reuse already recorded measurements only if the implementation, timing boundary, input, scheduling setup and full publication match.
3. Before confirmation, freeze the complete candidate, every tuning parameter, the evaluation manifest and its digest. Reserve whole locations, with all scans, offers and repeats at one location assigned together. For synthetic confirmation, draw fresh receiver sites and offsets independently of candidate results, cover different latitudes and both pilot edges, and include containing and omitted offers. Commit the seed and truth digest privately, give inference only opaque recordings, capture-time catalogues and offers, lock results, then reveal scores. Keep earlier public simulations and the new confirmation separate. Seek a fully compatible archived recording from a different physical station; until there is one, label geographic transfer as simulated and physical off-site performance as unverified.
4. On the fixed confirmation panel require both median paired candidate/baseline elapsed ratio and ratio of summed elapsed times at or below **0.50**. Count every assigned recording, including withholding and failure. An unexpected failure is a regression, never a shortcut. Report CPU seconds, wall time, run order, return coverage, returned-error median and P90, and all-recording cumulative position error for each calibration arm. Use the exact same raw files, offers and orbital snapshots for both builds.
5. For exact refactors compare per-recording decisions, owners, coordinates and published evidence. For approximate proposals our starting gate is conservative: on containing offers, preserve each baseline fix and avoid worse median or P90 position error per site and per calibration arm. Count newly issued fixes on withheld cases separately. On omitted offers allow withholding in place of a wrong baseline fix, require no additional false fixes, and report all remaining false fixes. Do not claim geographic reliability from a small or single-site panel. A design that misses the agreed gate stays experimental.

Production changes are outside this study. Each stage stops for review; 64 or a full replay requires an unresolved question.

### Blind search-region boundaries

Fresh panels assign four unlabeled offers to each simulated recording. One contains the receiver well inside the square. Two place it 50–250 m inside or outside the same face, with independent offsets along that face. The fourth puts the receiver far outside. Both center coordinates vary. Only the scorer sees the relationship to truth. Inference runs each offer independently and receives its own square. Reusing the waveform across offers holds signal quality and satellite visibility fixed. The two locations each require a separate recording.

The scorer reports each location, offer type and calibration arm separately. A lost valid boundary fix fails the quality check even when interior cases succeed. It also counts false fixes inherited from the baseline. Fresh validation requires coverage of all four offer types at each site. The public northern near-edge example motivated these controls and remains a development case. [Boundary experiment](edge-trial.md)

Each timed launcher must echo the assigned center, width and orbital screening center. Its published map inputs, grid and path must use that region. Comparing the two launchers alone could overlook a shared station default. We checked the original offer files against all twelve launcher receipts from the six saved integration pairs. All twelve matched. [Timed comparison and region checks](../../../tools/pipeline_eval/qualification/paired_publication.py)

The scorer rejects assigning two receiver locations to one waveform. Under the four-offer protocol each individual recording must cover all four offers. This keeps waveform quality and visibility fixed as the offered square moves. The score also exposes `candidate_correct_on_all_region_decisions`. This requires complete geographic coverage, a fix on every containing offer and withholding on every omitted offer. Read this alongside per-site position errors and the relative speed and quality verdict. A faster system can reproduce a baseline false fix. [Scorer](../../../tools/pipeline_eval/qualification/score_paired_holdout.py)

Use `passed_geographic_holdout` for qualification on the fresh simulated locations. It requires the four-offer protocol, correct region decisions on every assignment, the matched accuracy gates in both calibration arms and both 2× elapsed-time gates. The historical `passed` field measures speed and quality relative to the comparator and can be true when both builds publish the same false fix. Physical off-site validation requires a separate receiver recording with an independent location reference.
