# Cost of retaining deployed inference with the covariance receiver

Keeping the covariance receiver and lossless publication stages, and restoring the deployed solver, is estimated to cost **78–91 CPU seconds on DS30-0374**, **139–140 on DS30-0008**, **20.3–20.7 on public north**, and **19.0–19.2 on public south**. These are calculations from stored receipts. The corresponding CPU budgets for 2× are **63.78, 107.00, 16.49 and 15.17 seconds**. The public estimates refer to the original north and south waveform offers. For CPU, let `C` be the candidate's whole-process CPU, `E` its elapsed time, and `W` its middle elapsed interval. On a pinned single core the outer-stage CPU is between `C − W` and `E − W`. The lower end assigns the wait to the outer stages and the upper end assigns it to the middle. Add the archived standalone deployed solver CPU to both ends. This estimates the stage substitution under the recorded candidate's outer-stage cost and the archived solver workload. The ranges account for where wait could fall within the measured launch. ## One exact salvage opportunity

The fine salvage loop repeats each shortlisted satellite's entire knot bank 121 times so that the phase index doubles as a satellite row index. The interpolator then advanced-indexes those identical banks at the same track times and phase grid for every shortlisted satellite. A read-only broadcast of the single satellite bank can preserve the source values and returned array order. Compute the common requested times, knot indices, interpolation fractions and rotation coefficients once per track, keeping the original full vector shape and order. Fetch each candidate's own state values with those shared indices, then use the original per-row arithmetic, projection, cost, winner order and gates. Every supported window, satellite and phase is still evaluated. Require bytewise agreement of projected values, phase scores and the ordered fine alternatives before attributing any solver saving. [Fine salvage loop](../../../tools/pipeline_eval/variants/v5_tiled_salvage.py) · [Released phase interpolation](../../../src/leo/analysis/research/continuous_curve_fit.py)

The existing DS30-0374 profile attributed 2.492 seconds to fine salvage, with 0.621 in the curve profile and 1.253 in the noise screen. This proposal leaves those two measurements' worth of work in place. Crediting all of the roughly **0.62 profiled seconds** left to projection and setup would already overstate its potential on that recording. For DS30-0008 the earlier causal/salvage mode's entire salvage stage cost **7.11 CPU seconds**, so even removing that whole stage would leave most of the 23.48-second gap. The exact native Graph path is a measured complement of approximately **0.5 CPU seconds** on the dense input. The archived evidence supports these local savings and a larger remaining cost in full assignment, conservative fitting and inference.
