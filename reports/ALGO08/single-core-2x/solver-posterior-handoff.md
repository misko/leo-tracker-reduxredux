# Reuse the checked curved posterior in the predictive grid

On DS30-0155 the handoff reduced the complete grid from 5.181 to 3.595 CPU seconds, a 1.44× speedup for that stage. Both endpoints, owner maps and optimizer paths matched. Twelve out of 358 grid scores changed by one binary64 ULP, at most `7.28e−12`. The public southern model had no predictive rows and reproduced its grid exactly.

The selected grid recomputes each arm's robust curved posterior at every point. When the fit includes predictive rows, it then forms a second dense weighted precision from the curved design and factors it solely to whiten those rows. The native curved solver has already checked the same posterior in private-track blocks and a shared Schur factor. The overlay exports a Cholesky factor of the native posterior in private-then-shared column order. It uses the original private blocks, their couplings, and the already computed shared factor. Independent unused columns retain their own prior precision. The original coefficient scales and the permutation are applied to the predictive rows before triangular whitening. This yields the same covariance in exact arithmetic. [Native curved solver](../../../src/leo/analysis/localization_v4/native_bound.c) · [Stock predictive attachment](../../../src/leo/analysis/localization_v3/event_position.py) · [Factor export](../../../tools/pipeline_eval/variants/algo08_posterior_handoff.h)

The handoff is confined to the selected numerical grid. The whitening bases differ, so the conditional residual vector seen by a nonlinear optimizer would change even where its squared norm agrees. The fits, track and phase gates, selected owner assignment, and separately verified endpoint objectives continue through the original calculations. Inside the grid, a factor requires the success of that very native call and a finite positive-diagonal factor with all expected columns. Unsupported curved layouts, native fallbacks, unexpected event columns, or failed predictive arithmetic use the original dense path. The grid still recomputes both complete arm likelihoods at every planned point with the original sample order and time limit. ## Reproduce

Build the separate library with `tools.pipeline_eval.variants.algo08_posterior_handoff.build(Path(output))` in the deployed numerical environment. Run `solver_posterior_handoff_trial.py run RECEIPT FROZEN LIBRARY OUTPUT` under the shared low-priority Gauss CPU 2 lock, one numerical thread, and `PYTHONPATH=src:.`. `FROZEN` is `/tmp/leo-algo08v2-2x-bench/integration-full-float-pgo-signed`. For the physical receipt `/tmp/leo-full-float-pgo-signed-0155-run.json`, pass `--single-root leo-full-float-pgo-signed-0155`. For the southern receipt `/tmp/leo-algo08v2-2x-bench/paired-full-signed-south-inside/pair.json`, pass `--handoff-first`. The runner preserves both complete position grids and paths for each comparison. Each solve has an 88-second limit.
