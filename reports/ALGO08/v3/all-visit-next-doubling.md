# What would close the remaining gap to twice ALGO08v3 speed?

The most promising receiver still looks at **both antennas on every admitted visit**. It uses 8 ms for ordinary visits and periodically spends 20 ms on a two-scan anchor. On the North simulation this produced 112/128 m horizontal error in 10.828 s, against 106/141 m and 16.133 s for a fresh installed ALGO08v3 run. That is **1.49×** from original I/Q through all eight figures and exit on one Gauss core. The earlier v3 control took 16.761 s with identical scientific outputs, giving 1.55× against that clock. ## Put two engineering targets on the same clock

On all-visit North, authenticated acquisition took **5.074 s** and decision through publication took **5.174 s**, leaving **0.580 s** in the rest of the 10.828 s process. The latest half-time target is **8.066 s**. Even eliminating all **1.857 s** of native short-primary CPU would leave about **9.0 s** if the other elapsed costs stayed fixed. An example budget is **3.60 s acquisition + 3.75 s decision/publication + 0.58 s other = 7.93 s**. Both large stages would need to improve by roughly 28–29%. These are design targets. On the earlier guarded South build, a roughly 35% cut in both stages would be needed for its own half-time. Individual recordings help size experiments. Release qualification uses the paired median and the ratio of total elapsed times across the same roster. I would pair the independent receiver transfer in **#1** with the cheap proposal-recall test in **#2**. The former measures whether an accurate shorter physical receiver scales. The latter asks whether an entire solver discovery phase can be removed. Start with one dense saved recording and one contrasting geometry. Freeze a surviving combination before paired original-input runs on a small roster and blind geographic challenges. Expand only when both elapsed gates, fix coverage, position errors under both calibrations, withholding and the eight figures justify the server time.
