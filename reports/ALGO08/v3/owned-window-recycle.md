## Encoded ownership and the previous prefix clock

Both stock four-member children made **four paid synchronous compressed snapshots**, with **zero** speculative reads. The main-thread encoded read and authentication took **130.83 / 130.06 CPU ms**, including **60.69 / 61.71 ms system CPU**. This path uses the original bounded descriptor routine and reads the entire encoded member into one private contiguous snapshot before the original SHA and decode. The prior full normal run dispatched **11** speculative snapshots over two segments. The decoder in both scopes still borrows the authenticated encoded snapshot and retains a separate decoded window owner.

The cause is method dispatch. The research prefix adapter uses a subclass of the installed source. The first-map binding installs a local windows method directly on whichever class the scanner uses. Worker lookahead wraps the installed base class. The subclass's own method shadows that later base-class wrapper. The normal full reader installs its first-map windows method on the base class itself, so the later lookahead wrapper remains outermost. A component test uses those exact bindings to show one speculative submission on a synthetic normal two-member source and zero on its bounded subclass. This difference in scheduling belongs in comparisons with the earlier 1→4 slope. [Dispatch regression](../../../tests/pipeline_eval/test_resident_original_demand.py)
