## Invoke the batch entry

Use the installed v3 Python with `-IB`, and run under the same low-priority
single-CPU lease as the installed comparator. The candidate command uses the
same four recording, causal archive, region and output arguments as stock.

```sh
python -IB integrated_original_batch.py \
  --recording "$recording" --archive "$causal_archive" \
  --region "$offer" --bulk-root "$fresh_output" \
  --authority "$detached_request" --authority-sha256 "$request_digest" \
  --build "$frozen_build" --build-sha256 "$build_digest"
```

The external request schema is `algo08v3-original-request-v1` with exact
fields `schema`, `recording`, `session_id`, `inventory_sha256`,
`raw_authority_sha256`, `window_count`, `causal_cutoff_utc_ns`,
`archive_sha256` and `region_sha256`. The archive digest covers the
original basename-to-body-digest mapping for the capture's enrolled causal
view. The authority path and its detached SHA-256 come from the trusted
controller. Use absolute direct paths, an unmodified stock recording name
and separate fresh output directories for each arm. The exact input path
is part of the stock inventory identity.

`--prepare-authority NEW.json` derives that request using the installed
`FastScanStore.inventory` reader, signed typed indexes, hardware clock
bracket and causal roster. The controller can independently reconcile it
with its enrolled authority before scheduling. Both `--prepare-authority`
and `--preflight` reject original waveform opens through their metadata
scope. Preflight verifies the detached request, all expected stock metadata,
both input roots and the frozen build without starting a detector. A
wrong manifest, causality, build, unsupported original layout or missing
artifact reports a failure before a successful release marker is possible.

The standard receipt is emitted as JSON on stdout. A successful complete
or withheld run also publishes `algo08v3-successor-release.json` inside
the fresh output, with schema `algo08v3-integrated-original-release-v1`,
the build and authority digests, ordinary session and run ID, terminal
digest, decision and stock-shaped receipt. A successful withhold retains
the original withholding reason, null calibration endpoints and normal
failure/no-fix evidence. A failed process may leave diagnostic files. Use
the exit status and release marker together before advancing its case.
The standard terminal and localization stores remain in their existing
locations. The original verified held-anchor witness is a sibling named
`<fresh_output>-held-anchor-route.json`, which the controller should retain
with the job artifacts.
