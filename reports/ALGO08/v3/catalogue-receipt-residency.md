## Verified reconstruction limit

The standalone verifier opened only local NVMe run receipts and the pinned durable portable artifact. It reconciled both original build and archive authorities, reconstructed the digests of both accessed subsets and parsed the portable digest headers. This cost **27.1 ms wall / 21.2 ms CPU** once in the offline readout. It performed zero TLE body or waveform opens and launched no solver. Four component tests passed. They cover the distinction between opened and enrolled rosters, invalid index extents and indirect receipt paths. This validates historical access accounting. It supplies no independent saved location or qualified timing. [Verifier](catalogue_receipt_residency.py) · [Focused tests](../../../tests/pipeline_eval/test_catalogue_receipt_residency.py)

A future exact zero-backing replay needs the full enrolled ordered roster metadata and readable original text for every body the replay requests. An authenticated local content store could keep each distinct body once and map each collection-stamped reference to its original digest. It would still need to check every requested name, cutoff and body and fail closed on a missing digest. Changing detector or offer can change the demanded bodies. Capturing the earlier run's read set would support an unchanged control, with any extra reads for a changed input remaining unqualified. Charge unique body capture and verification when creating such a store and charge local authenticated reads at replay. The existing 2.689 MB index can accompany that store as parser metadata. The current evidence cannot reproduce either solve from it. No new read or lease is needed for this finding.
