# Decoded-block authentication fusion on original input

Decoded-block authentication fusion has insufficient headroom for the current 2× target. The exact same original-input worker would still overshoot half of fresh installed time by **0.408 / 0.549 s** across the two saved orders even if its entire decoder, frame checksum and decoded SHA-256 processing became free. Fusing authentication into native block delivery can save only a fraction of that scope. The independent first-member assay and both complete originals already measured the proposed boundaries. This audit used those receipts without a new worker or waveform read.

## Actual path and remaining reuse

The sparse 20/8 receiver processes both radios on every admitted visit, with both scans on the original 20 ms anchors. The ordinary input path is `--verify-original-once`. It authenticates each encoded snapshot, performs one continuous original Zstandard decode and frame checksum, then checks the original individual window and complete decoded-member SHA-256 values. The direct output path uses owned window buffers and retains at most the previous live buffer for history. The variable-extent case uses the original ring. The original digest checks include excluded windows. It builds no replay map or prefix hash. [As-run original composition](integrated-original.md) · [Verify-once input](legacy-verify-original.md)

One possible original-format implementation would update the two SHA states immediately after each decoded block, with the split at the next signed logical window. It would still seal each output only after its own original SHA validates and still check the complete original extent, frame checksum and member SHA. This may improve cache locality or reduce dispatches. The current SHA-NI paired routine already loads each full 64-byte message block once for both SHA contexts, shares the word schedule and performs the two separately seeded rounds. Moving the update into the decoder therefore cannot remove a second pass over the decoded window for the other SHA. The prior whole-owned-arena fusion already put decode and hash behind a native call. The newer direct-to-window path changed ownership and avoids another copy, so crediting both earlier improvements to one proposal would count the same traversal twice. [Paired hash implementation](../../../tools/pipeline_eval/variants/experimental/paired_sha256.c) · [Earlier native merge](fused-block-input.md) · [Direct output and prefix hash](legacy-first-history-fast.md)

The one exact missed state reuse is at the first signed window in each member. Both chains start at the SHA-256 initial state. A single update can cover the identical payload prefix, followed by finalizing a copy for the window and preserving the unfinished context for the rest of the member. Later windows restart from the standard initial state while the member chain continues from its previous bytes. Later common data still allows a shared message schedule, as in the current kernel, but it does not give identical input state to the two compression operations. Using the largest signed window per member gives **350,000** potentially shared 64-byte blocks on the two recordings, below **0.84%** of the two decoded chains' full payload block operations. That is an operation-count bound for this exact first-window reuse, with padding excluded and partial-window rounding included. It is not a timing estimate.

## Saved physical first member

The independent original-source arm on DS30-0016 member zero used the current native history, hash, sparse short and full anchor binaries. It verified all 78,554,951 encoded and 102,400,000 decoded bytes, 64 issued rows with 58 admitted stereo visits, both antennas and 43 signed factors. The original path charged **60.558 ms CPU** for native decode and frame checks and **24.230 ms** for decoded SHA. All of that work together was **84.788 ms CPU** out of 351.893 ms acquisition. It had 8 full and 50 short visits, which read 44,800,000 logical bytes for DSP. Its encoded authentication happened to cost 128.038 ms, versus 32.222 / 32.954 ms for that same member in the integrated original runs. This receipt uses the slower independent encoded snapshot cost only in its own boundary. The complete-case bound uses the two actual integrated clocks. [Saved physical member](integrated-packed-cost.md)

The complete fixing capture authenticated **1,292.8 MB** decoded and used **545.6 MB** for DSP. The tiny withhold authenticated **44.295 MB** decoded and used **24.960 MB**. The remaining **766.535 MB** including all excluded samples is still subject to original complete decoded and window SHA as well as Zstandard checksum and extent verification. Saving bytes from the DSP aperture gives no authority to skip those original checks. Neither original provides an installed per-prefix sample authority that would change this rule. The earlier prepared archive used a different existing custody proof and is separate. [Prepared-source trial](integrated-packed-full.md)

## Disjoint limits using both current timings

Fresh installed elapsed totals 12.134326 s. The integrated original sums of 7.561986 and 7.711868 s have gaps of **1.494823 and 1.644705 s** when priced using this fresh denominator. Each row below is an optimistic independent scenario. It subtracts each selected observed wall interval once and keeps all other intervals, the native schedule, selected outputs and position work at their actual clocks. Prefetch work can overlap acquisition, so worker CPU is recorded separately and never added to removable wall time.

| Work credited for free or halved | First order wall credit | Reverse wall credit | Remaining gap, first / reverse |
| --- | ---: | ---: | ---: |
| Both decoded SHA checks | 0.314 s | 0.316 s | 1.181 / 1.329 s |
| Entire decoder, frame checksum and decoded SHA | 1.087 s | 1.096 s | 0.408 / 0.549 s |
| All acquisition outside native callbacks | 1.455 s | 1.523 s | 0.039 / 0.122 s |
| Every short native callback | 1.051 s | 1.066 s | 0.444 / 0.579 s |
| Every full and short callback | 1.572 s | 1.589 s | 2× exceeded by 0.077 s / 0.055 s still required |
| Half of complete native callbacks and half of decoder, checksum and decoded SHA | 1.329 s | 1.343 s | 0.166 / 0.302 s |

Earlier signed experiments tested alternate Huffman tables, a read-assembly toggle, owned decoded allocation, synchronous demand reads, fixed shared timing and carrier banks, and cross-lag and shortened confirmation. The current native sparse carrier sweep already captured the exact eligible-bin improvement. The observed gains or scientific failures in those experiments give no additional independent savings here. On these physical originals a credible path to halve the total needs to reduce more than one major interval, or pair acquisition changes with further saved-publication improvement.
