## Authentication and costs

Map creation exhausts the released reader over the original member. This verifies the original compressed SHA-256, index SHA-256, each full-window SHA-256, complete decoded SHA-256 and frame checksum. The detached map commits the original manifest, index, member, decoded identity, partition, all 64 prefix hashes and exact exception bytes. The reader requires an external map pin and independently checks its layout against the authenticated encoded input. Any result that intersects the exception is assembled from ordinary decoded spans plus the certified exact bytes, then checked against the full original signed window SHA-256 or the pinned prefix SHA-256. Flipping one byte inside the skipped encoded block made both stock and selective paths fail before the first visit. Flipping one byte in the detached exception caused pin rejection. ## Other original members

Whole-member exclusion would lose otherwise usable blocks. A separate original DS30-0016 census found 13 sequence-bearing blocks and just 81 match bytes across eight of 13 members, covering 488 of 808 visits. Full decoded exceptions would add at most 1,703,936 bytes to 991,734,597 encoded bytes across the recording, before map metadata. Four exception blocks introduce a new Huffman table. Just one has an ordinary treeless consumer before the next table. It is block 232 in the last member, which contains 40 visits. A reader that handles isolated exceptions alone must still replay unsupported members entirely, including this 40-visit member. The dense prototype is scoped to a single four-byte match and does not enroll the other physical members. [Separate sealed dependency census](/dev/shm/leo-original-frame-coverage-0016-02.json)

A non-isolated table owner can be approached by sending the authentic literal header and literal section to a private decoder with a zero sequence counter appended in scratch. Its decoded literals only seed the table. A later treeless block still uses its original encoded bytes, while requests for any part of the owner use the pinned exact exception. The legacy native decoder can seed at the owner’s real ordinal so subsequent lookups recognize that state. The isolated prototype declines this layout; the prospective method owes its scratch, table replay, extent checks and byte verification under original inputs. An alternative smaller representation for an isolated one-match block could store the insertion offset and the exact four matching bytes, then reconstruct from the genuine literal stream. It would add a literal decode on requests for that block and save no decode on this original short schedule. Neither mechanism was timed here.

The absent-sidecar and unsupported-layout adapter may decline before selective issue. A failed prefix or full digest taints the current instance and propagates as corruption. A native decline after a request cannot switch to stock for subsequent visits in the same attempt. A stock retry would need a fresh reader and discarded partial detector state. This closes the measured member’s integrity and fallback boundary with no production integration.
