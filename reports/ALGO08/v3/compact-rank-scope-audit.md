## Why there are twice as many calls as builds

The two paid centre seeds each run one initial association and two updates, with four more updates at the original corners. Every `explore` makes two source-level calls with the same proposal, base object, point and method. The installed-scoped `dense_discovery` wrapper returns the first result for the identical second call. The ten actual associations therefore consist of six distinct centre states and one state per corner. The catalogue block scorer retains one index per curved track for the centre base, discards those indexes when the base changes, and builds one set for each corner. All three receipts reconcile without an ordinary retry or full block fallback.
