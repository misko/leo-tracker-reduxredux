# Bounded compressed streaming and one-time private slot allocation

The earlier incremental trial already hashed bounded compressed chunks as ordinary Zstandard consumed them and kept detector rows private until full authority succeeded. The missing performance comparison would pair a fixed reusable compressed feed and bounded decoded windows against the current asynchronous reusable slots. Existing steady-state copy and hash costs leave only **about 4–6 ms per warm member** of observed encoded-side opportunity before charging any decoder or scheduling change. No additional raw trial was run. The larger, simpler opportunity is to avoid growing the existing slots after their first allocation. ## Authenticated input and commit scope

The public `ShortWindowReader.windows()` authenticates the index and the complete encoded member before supplying any decoded sample. It then verifies geometry, consecutive index offsets and each window SHA-256 before yielding it, and checks the independent whole-decoded SHA-256 and decoded extent at exhaustion. Processing a sequence of hashed encoded blocks ahead of the final encoded digest would change that public reader contract. Inside a private receiver acquisition, the normal scanner holds detector rows and chronological continuation state until the complete ordered recording traversal returns. It writes `detections.json` only after `acquire()` returns and calls the numerical solver later. This gives a possible private transaction boundary for early CPU work without externally releasing an unsealed packet. [Public member reader](../../../src/leo/storage/short_window.py) · [Original detector and commit control](installed-receiver-control.md)

A complete one-pass private design could read each ordered byte through one fixed 256 KiB destination, update the encoded SHA over that exact view, and pass the same view to ordinary pinned Zstandard. It cannot refill the destination before the decoder consumes that view. An explicit native streaming consumer can keep a separate bounded decoder history and owned verified windows. A single bare `read()` memoryview shared between producer and decoder would need a proven lifetime or independent leases. Early windows, continuation and receipts must remain provisional and be discarded on any abort. Authentication still requires a pinned original member index, ordered signed window identities, each original decoded SHA, full decoded length and SHA, exact Zstandard frame completion and checksum, encoded size/EOF/SHA, pinned directory, and final descriptor/path identity. The digest checks cover bytes independently of size and timestamps. A corrupted or truncated tail can invalidate all previous provisional DSP, and no partial packet should become visible. [Independent inconsistent-hash fixtures](native-verified-drain.md) · [Earlier staged streaming late-failure check](incremental-ingress.md)

The existing native sealed stream already reuses a 256 KiB input buffer and feeds the exact chunks it hashes to pinned Zstandard, but retains a 102.4 MB decoded slab until full member verification before DSP. The native drain bounds decoded scratch at 1.6 MB and still keeps the complete authenticated compressed snapshot. The fused ring bounds only decoded history and likewise retains the existing encoded snapshot. The Python incremental trial reduces both input and output window retention and performs preliminary DSP, while obtaining newly allocated bytes from `os.read` and performing the old whole-read comparison. Its measured-arrival CPU reduction on one resident member was 2.8–5.1 ms across both orders. Its final-checksum failure discarded 50 completed stereo callbacks and emitted no packet. The alternative holding delivery until the observed cold read completion improved seal time by 2.42–2.60 ms. None of these studies measures a fixed-source, bounded-output asynchronous port against the current slots. [Whole decoded slab](sealed-stream.md) · [Native drain](native-verified-drain.md) · [Bounded decoded ring](fused-window-ring.md)

Replacing the two observed 78.66 and 78.79 MB compressed slots with one or two 256 KiB rolling destinations would materially lower explicitly retained encoded capacity. RSS would also include decoder history, owned live windows, detector state and ordinary runtime pages. That process reduction remains unmeasured. The bounded descriptor still copies every encoded byte from the kernel into userspace; it could reduce repeated memory traffic from touching pages and consuming the same bytes in different passes. It does not eliminate physical I/O, the encoded SHA or decoding. An asynchronous small-buffer producer additionally needs to retain sufficient read-ahead for cold cases without weakening the existing checks. The current whole-member lookahead already overlaps paid prior-member work with storage wait. [Original ready-work trace](ready-io.md)

## Reserve the existing slots once

The observed 0016 slot capacities enlarged from **78,460,708 to 78,664,842 bytes** and from **78,744,802 to 78,794,383 bytes**. Each resize obtained a new private allocation even though the extra extent was small. A lazy one-time capacity per slot equal to the maximum **78,794,383-byte** eligible member in the already verified roster would remove these two resize events. The two equal final allocations would total **157,588,766 bytes**, only **129,541 bytes** above the measured final slots. The receiving view would still be sliced to the requested exact size before `readv` and digest checks. At the measured retained-buffer read rate, the two growth reads would cost about **23 ms** for the same bytes once the pages are present. Their observed 234–248 ms establishes a size of the issue, with about **211–225 ms** modeled as a difference under that assumption. The first two real allocations, new endpoint pages, all copying and digests remain paid. This reservation was not timed. [Current increment-on-demand allocator](legacy_snapshot_reuse.py) · [Existing bounded lease binding](prefetch_snapshots.py)

The lean implementation can consume the maximum already declared in the original intake's ordered signed member roster before the first speculative read. It can reserve that capacity lazily using the existing ownership guard. Two equal maxima avoid depending on even/odd order after speculative failure, cancellation or a still-retained view. The branch therefore keeps the existing refusal to overwrite a live lease and the same ordinary fallback and exact upper bound. A case with no eligible lookahead needs no slots. This requires neither a new payload read nor a different decoder or publication contract. It only addresses the speculative slots. The first member read on each segment remains ordinary.
