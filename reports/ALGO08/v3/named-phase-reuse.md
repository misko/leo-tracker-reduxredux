# Exact reuse inside the original signed final refit

The scoped DS30-0008 replay reproduced both original signed positions, RF RMS values, objectives, last phase changes and the accepted paired gate. Both arms retained the same 4,367 observation/satellite/role triples. The signed pair cost 2.168 CPU s in this replay versus 3.591 CPU s in the sealed historical run. Most of that clock difference came from its fitted arm and cannot be attributed to the measured reuse. The fixed-arm clocks were 1.136 versus 1.194 CPU s and the fitted-arm clocks were 1.031 versus 2.388 CPU s. The historical run lacks the operator-level timings needed to explain the gap. The original optimizer requested `15, 12, 6, 3, 3` residuals by refresh in each arm on the flagged path. All 78 requests were distinct within their own numerical phase. The simulated released last-eight cache and the implemented 64-entry residual cache had zero optimizer hits. The largest live residual cache held 15 payloads, about 1.05 MB plus keys. The ten refreshes used nine byte-distinct references. Only the initial zero reference was common to both arms. Reusing a result at a common coordinate across the other refreshes would reuse a different likelihood. The older fixed regional optimizer also has a scoped memoization port. This run gives no reason to add a larger memoizer to the signed optimizer.

Two exact changes removed identifiable duplicate work. The epoch layout now reuses the arm-private original rows, aliases, stable hardware and noise, selected powers and normalizer. The existing selected-design kernel still processes actual site-dependent rows on every call. The summary now reads the curved part of the cached endpoint before its scalar entries are updated by the predictive calculation. This avoided two complete curved operations, around 23 ms at the observed mean, with the usual curved calculation available on a cache miss. The archived run did not partition setup, so the avoided cost of eight constructor pairs and 78 invariant slices cannot be measured directly from its clock.

The existing grid-only geometry preparation also applied inside the signed refit. Its original and prepared arrays matched on the ten checked first coordinates, with zero fallback. Pricing the original method at the observed mean of those checks gives approximately 0.105 CPU s for 78 calls, versus 0.074 s paid for prepared geometry and its checks. The roughly 0.031 s difference is a projection from first coordinates. The evaluator's 0.903 s curved and 0.448 s predictive covariance remain site- and phase-dependent. The remaining 0.675 s inside the objectives includes the original retained-posterior Gram and other operations, with no separate attribution to each. The existing native grid covariance handoff uses a different numerical factorization and was outside this exact comparison. The observed reuse supports small deterministic savings and gives insufficient attribution for a recurring 1.423 s speedup.
