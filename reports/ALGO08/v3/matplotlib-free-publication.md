## Who loads Matplotlib

The actual positive callback first loads the installed `tools.algo08_position`. Its scientific `prepare_packet` depends on `localization_v3_orbits`, which imports three orbit record types from `leo.presentation.orbit_plot`. That module also imports Matplotlib. This branch pays **141.4 ms CPU** inclusive inside the first position import. The scanner then imports `fast_standard_analysis.render` eagerly, taking **11.2 ms** including its own first-load children after the position import. The installed publication's lossless encoder imports Matplotlib's image writer and the Agg layout/shared orbit modules. In the six-Cairo renderer, the orbit scene still uses `orbit_plot` for folding, alias breaks and validation as well as Matplotlib's `turbo` palette. The Cairo callbacks pass the image writer to the PNG encoder for its dummy metadata PNG.

The dependency arises because the render-neutral orbit records and evidence production live on the same import path as artists. The current positive timeline stops at the actual renderer callback's handoff request boundary, after the installed position/scanner imports and source-guarded grid setup. It prices that first-load scope rather than interpreter teardown or an independent full-process repeat. ## What a general renderer would have to preserve

A Matplotlib-free route can keep the scientific packet. Its import boundary would move the three orbit record types and validated frequency folding into a render-neutral module, retain the original import aliases for existing callers, and expose a checked renderer port to the scanner and lossless publication. The Cairo layer would reuse pinned package-level turbo, tab20 and reversed viridis lookup data, plus the existing PNG metadata and libdeflate contract. These populate presentation values after science. Exact catalogue and phase computations stay on their existing ports.

The remaining map needs both endpoint projections in the supplied frame, exact grid scores and missing markers, a correctly scaled colorbar, the equal-aspect regional panel and fit zoom, both arms' recorded paths, phase-round annotations, and the title and footer. Track RMS needs the original per-fragment grouping, stable descending order including ties, fragment IDs, bar values and all recorded labels with enough room to show them. Scene validation and unsupported-input fallback must work for different region widths, geographic centres, tick ranges, fit paths and label lengths. A fallback also pays the ordinary plotting imports if it runs. This experiment made no replacement artist or offsite rendering claim because the cost screen stopped before prototyping.
