## Smallest useful next-study plan

1. Freeze these four exact recording/session identities and one fixed correction policy before correction outcomes. Validate complete public tracking contracts and reconcile manifest/index authority, following the existing `readiness/validate_panel.py` port pattern. The inputs are existing recordings; no RF collection is required.
2. Use `tools/prepare_algo02_ds23.py --run-dir NEW_ROOT --case LABEL --stage export`, then `--stage prepare`, after a sample-compatible authority is frozen. Preparation constructs the original graph, nominal noise, causal current/previous TLEs and phase history without using GPS. A matched original baseline must then reproduce its declared research parent. Do not treat the production position-stage completion flag as this reproduction check.
3. For a lean transfer, retain the prior RF-only target/control selection rule and **complete** owners, with all selected IDs and a physical-window count frozen before detector outcomes. All other likelihood rows remain unchanged. Report corrected measurement coverage separately from the fact that position inference still uses the full original curved-plus-predictive likelihood. Match c0/fitted-c, budgets, starts, phase refresh, aliases, noise and gates; retain unavailable and unqualified cases with declared fallbacks. Seal RF results before geographic evaluation. Known or unknown historical exposure remains part of the interpretation.

Budget feasibility is conditional on the eventual owner counts. The completed two-scan transfer used 151 new paired calls and about 326.7 process-seconds, roughly 2.16 seconds per call on this machine. At the previous 75–84 complete selected IDs per scan, a four-scan panel would require approximately 300–336 calls, or 650–730 worker-seconds before parent preparation and reference fits. This is a planning estimate, not a measured runtime or performance claim for the new block. Count exact physical-window deduplication first; stop or report unavailable if a predeclared cap cannot cover whole selected owners, rather than trimming or substituting owners.

Whole-likelihood refinement is a materially larger experiment. The previous baseline response designs contain 2,241 and 3,186 unique likelihood IDs per scan. A naive one-call-per-ID estimate is about 81–115 worker-minutes per scan at the observed rate, before deduplication and fits. Actual paired-window overlap could reduce this, but it has not been counted for the new four. A whole-likelihood launch therefore is not justified by this metadata check and risks returning to a multi-hour campaign.
