# Prepared FFT workspaces for the original capture detector

The prepared FFT kernel reduced median full-detector CPU by **16.9–22.7%** across four recordings relative to the previous compiled implementation. It preserved the installed detector’s complete ordered public output in **16/16 new-window, 6/6 stress-window and 8/8 synthetic comparisons**. This includes every accepted or rejected candidate, original physical receiver and capture clock, fractional epoch, CFO and gate decision. ## What the measurements changed

The prior batched bank regenerated reference spectra, plans and scratch on every receiver acquisition. A representative 12-anchor, 21-carrier grid spent about 92 ms in that native body, dispatching 104,286 carrier inverse transforms and rebuilding 252 reference transforms. The hot normalization paths compiled to scalar square roots. The new kernel reuses reference spectra, forward and inverse plans, and scratch buffers across calls. It keys four process-local entries by exact coefficient bytes, carrier bits, rate, anchor lengths and order. It retains neither completed scores nor IQ from prior visits. Overlapping 44-tap sample supports use one inverse received-energy norm per input window location, with the normalized template weights factored out. The fold uses vector square-root instructions. Sample boundaries and the original frame and anchor counts, support totals, CFO rows and every candidate epoch remain in the calculation. On the genuine new and stress windows, 46 of 54 prepared receiver-grid calls reused an existing entry. The old bank constructed 15,708 reference FFTs and the prepared bank constructed 2,856. Both calculated 23,058 signal forward FFTs and 6,498,954 inverse FFTs. The prepared 12-anchor grids took 52.91 ms median CPU on four first preparations and 52.08 ms on 40 reused keys, versus 92.34 ms for the old path. For 22 anchors, the corresponding medians were 99.58 ms on four first preparations, 94.85 ms on six reused keys, and 174.51 ms for the old path. Most of the measured kernel gain comes from sharing and vectorizing normalization. Warm cache hits remove reference work even where the initialization clock is a small fraction of execution. One published 22-anchor cache entry uses 2,072,576 bytes of named FFT buffers. The four-entry bound excludes small key structures and FFTW-owned plan allocations. ## Numerical scope and install

The eight real primary grid comparisons cover 2,239,944 cells. Their largest absolute score difference was **1.39 × 10⁻¹⁶** from the prior batched implementation and **2.29 × 10⁻⁸** from the installed direct grid. All eight had identical ordered retained basin keys. The smallest observed gap between the next eligible retained peak and its nearest score competitor was 1.56 × 10⁻⁵. No audited retained step lay within twice its observed grid residual. This is an explicit recorded near-tie audit. It supplies no certificate for arbitrary closer scores in future inputs. The synthetic zero windows returned no gated candidates, and the same signed noisy ±720 kHz controls retained the original outputs. The exact installed archive projection also reproduced the new and stress clocks and factors. [Order and score audit](grid-audit.json)

The [x86 shared library](original_kernel.so) is 28,904 bytes and links to `libfftw3f.so.3`. The new source adds 120 Python and 115 C-header lines by composing the frozen FFT bank and port. Use `tools.pipeline_eval.variants.original_kernel.PersistentGrid` in a dedicated installed producer process and keep the same instance across visits. `grid.route(acquisition, screen)` replaces the same coarse port used by the prior bank. Wrap each visit in the already-qualified `capture_exact_trial.refiners` context to obtain the measured combined path. Use the exact `cfo` and `fused` libraries in the input lock with the prepared library. Release plans at worker shutdown with `grid.clear_cache()`. For persistent raw replays, clear `grid.calls` per visit after collecting diagnostics. Cache hits return `filter_ffts = 0`. Unsupported coarse arguments use the installed direct scorer through the existing adapter. The detector measurements cover native x86 saved IQ. Whole-recording parity, physical embedded runtime and position performance are outside this report.

The first input-preparation attempt used a direct file read that the capture archive account did not permit. The final run used the existing authenticated read-only capture reader and unchanged window selection. No scientific result was produced by the first attempt.
