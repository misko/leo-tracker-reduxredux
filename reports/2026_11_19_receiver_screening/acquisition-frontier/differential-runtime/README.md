# Runtime integration of the differential pilot scout

The opt-in saved-IQ worker runs the frozen 44-sample differential scout on every valid dual-receiver window. The sample buffer is signed 16-bit little-endian IQ at 10 MS/s with the receive lane on the middle axis. Each lane contributes its first ranked positive peak to the qualified hinted wide detector. The detector retains its existing four-center budget, absolute CFO search and fractional gate. The whole-IQ service continues through the ordinary authenticated factor assembly, causal request and compact position receiver. Its plan binds the source closure and exact native library. Incremental `differential-visit` rows in the two raw-lane logs retain proposed centers, whether native selection changed, and split process CPU and wall clocks.

On the separate runtime panel, the exact Python integration reproduced the direct scorer's complete proposal vectors, native traces and canonical payload in all 46 dual-receiver windows. The independent FFTW implementation reproduced every rank vector on all 92 physical lanes and every native payload in 46/46 windows. This included 32 authenticated saved visits from four recordings and 14 planted, CW, noise and zero controls. The largest score-surface error on any lane, normalized to that lane's maximum absolute reference score with a floor of one, was 6.22×10⁻⁷. Among the 88 lanes with at least two proposals, the smallest relative margin between the top two scores was 0.00105 and the largest change in that margin was 7.77×10⁻⁷, both scaled by the top Python score. The FFTW implementation executes equivalent correlation formulas with a different float32 transform and uses the frozen Python ranking rule. It takes its reference spectra and normalizers from the actual Qin exact/control template generator at the bound edge and caches them for the context.

These clocks include conversion and ranking in the scout and the decoder on one pinned host core. All 96 repeated saved-window calls in each backend exceeded 20 ms when the wide gate was included. Each of the two separate single-context one-frame processes ran 20 visits with one BLAS thread. Linux `VmHWM` was 155,008 KiB for the Python scorer and 146,900 KiB for FFTW. `VmHWM` is the current process image's high-water mark. Its receipt also exposes `ru_maxrss`, which can retain a higher inherited maximum across `exec` on this host. FFTW planning and reference construction happen when the context opens and are outside its warm call timings. The complete saved-IQ service uses the exact Python route. The FFTW panel measures a detector stage and supplies no board clocks or location accuracy.

## Reproduction

The complete opt-in Python path accepts the same arguments as `tools.pipeline_eval.whole_iq run`. Use `python -m tools.pipeline_eval.qualification.differential_runtime run`, an existing receiver installation, two available cores, a new local output directory and a bounded time limit. Use `/srv/bulk/leo-dev/receiver-screening-20261119/differential-runtime/release/libleo-adaptive-detector.so` with `--detector-sha256 418e6d7569e73e2eb8b5107b50edf803d4d7271f1e863ffbba9c6b3c08380bd1`. The byte-identical readable copy comes from the existing hinted-build receipt bound in [plan.json](plan.json). The service keeps the normal 512 MiB memory limit and zero swap.

To reproduce the stage comparison, compile `tools/pipeline_eval/variants/differential_runtime_fft.c` with `cc -O3 -ffp-contract=off -Wall -Wextra -Werror -fPIC -shared`, naming `libdifferential-scout.so` in the local release directory and linking `-lfftw3f -lm`. The tested compiler was GCC 15.2.0 and the FFTW ABI was `libfftw3f.so.3`. Run `tools.pipeline_eval.qualification.differential_runtime_eval` with a fresh `--work` directory in the order `freeze`, `paired`, `python`, `fftw`, under single-CPU and single-BLAS-thread affinity. [Per-visit data](stage.csv) and [the archive receipt](prediction-lock.json) bind the native, source, sample and timing evidence.
