# Independent methodology review

Scope: frozen native GLRT changes and saved-IQ reporting only. This review did not run hardware or modify production sources.

The final v3 source was reviewed after the 1,520-call non-PGO panel. No hidden
lifecycle, failure-cleanup, namespace, or ABI defect was found in the persistent
fine-plan and lazy prepared-buffer changes.

## Resolved findings

- **The four-frequency tile preserves the scored arithmetic.** Each frequency retains the original four FP32 sample lanes inside each 64-sample block and the original block-major, lane `0..3` FP64 reduction. Frequency operations are interleaved but independent. The mixed-grid dispatcher tiles only bins satisfying the existing exact `f0 + f*100` comparison; irregular bins retain the cached FP64 rotation path, and untiled regular tails retain `full_blocked_dot`. The ARM differential receipt reports exit zero, and host tests compare direct dots and complete clipped-grid score arrays bit-for-bit across all four rates, partial support, and zero energy.
- **The ablations isolate both changes.** `LEO_NATIVE_GLRT_SCALAR_BOUNDARY_DOTS=1` keeps cached irregular rotations with the prior scalar dots. `LEO_NATIVE_GLRT_UNCACHED_BOUNDARY=1` restores literal per-frame irregular rotations. Neither switch changes candidate budgets, frames, bins, final GLRT, or other numerical defaults.
- **Persistent preparation is failure-atomic.** Growth allocates a complete replacement before releasing the prior buffers. A failed reserve leaves the context's existing buffers valid. Creation releases partial detector state and any reserved buffers on failure; destruction releases the persistent buffers. The process-wide entry guard continues to serialize mutation of the context.
- **The persistent fine FFT workspace has explicit context ownership.** Context creation initializes the FFTW input, output, and plan only after the search workspace exists; every partial-create failure and normal destruction path releases it. Per-search caches borrow that workspace without destroying it, while the compatibility entry points create and release a local workspace. Cache-entry spectra remain per-search allocations and are released on success and error. The process-global entry guard prevents concurrent use of a context-owned FFTW plan.
- **Prepared-view restoration covers search failures.** `leo_full_search_run_prepared_with_fine_workspace` restores the search workspace's owned raw, normalized, and prefix pointers after every `leo_full_search_run_ingested` result. The outer analyzer retains context-owned sparse buffers across eligible calls, frees call-local buffers on every exit, and commits neither result nor profile on failure.
- **The private helper remains namespaced.** The borrowed-workspace entry point is declared only in the private full-search header and mapped to `leo_native_glrt_private_*`. The archive symbol test rejects an unprefixed export. The public addition is an opaque profile API and appended public type; it does not change the layout of an existing public result or expose the private FFTW workspace.
- **Sparse preparation preserves conversion arithmetic and its valid view.** For the 120 ms dwell/120 ms stride geometry, only the first 20 ms is converted because the sole scheduled search has offset zero and consumes exactly that interval. Proposal generation continues to read the original 120 ms CI16 input. Other geometries retain call-local full preparation. Component tests compare sparse rows with the corresponding dense rows at every rate and include repeated-context, invalid-call, zero, random, and extreme CI16 cases.
- **Current-native exactness and frozen-reference recall are distinct outputs.** Exact comparison removes only row timing dictionaries, retaining ordered candidates and every row counter. Frozen dense recovery continues to use the historical positive threshold and tolerant bipartite epoch/CFO matcher. The comparison metadata states that this recovery is not exact current-native equality.
- **Timing scopes are internally disjoint.** Profile stages cover per-call allocation, preparation, proposals, search, and cleanup. API call time surrounds the whole analyze call. End-to-end call arrays additionally include thermal/RSS reads, serialization, output, and flush. Thermal distributions no longer carry millisecond deadline counters.
- **The final tile decision is measured.** On the real clipped worst case, ordinary tile4 scored the conditioned stage in 43.58--43.94 ms while tile2 required 47.17 ms; forcing `noinline,noclone` changed tile4 by only about 0.36 ms. The earlier four-bin spill concern is therefore resolved for the non-PGO release. The PGO regression was specific to a training panel that omitted the exact clipped context, rather than evidence that tile4 itself was slower.

## Unresolved risks and interpretation limits

Publication update: the subsequent sustained test completed 1,600 calls with
unchanged candidates and RSS plateauing after the first 16 calls; cold CLI
measurements are 210–360 ms. Final physical memory boundary tests pass
7.5 MS/s × 360 ms and 10 MS/s × 240 ms, while 10 MS/s × 360 ms retains its
known allocation failure. These results address the pending stress evidence
below, but do not replace exhaustive allocation-failure injection.

- **The tile's local arrays assume `nf <= 64`.** All current conditioned call sites generate at most 41 regular bins plus one clipped endpoint, so the production geometry is within bounds. The final score loop indexes the 64-element `tiled` array unconditionally, however; a future caller expanding `full_conditioned_scores` beyond 64 bins would require an explicit fallback guard around that lookup. This is a maintainability constraint, not a current qualified-path failure.
- **Persistent allocation moves cost and memory outside call profiles.** The dual-RX 20 ms buffers and fine FFT plan are retained until context destruction. Per-call preparation and planning improvements therefore must not be described as total lifecycle savings. The required cold-start and memory stress results remain the evidence for this tradeoff; the 1,520-call warm panel alone cannot bound creation latency or retained RSS.
- **Allocation-failure coverage is structural rather than injected.** The reserve path is failure-atomic and the borrowed/local FFT ownership branches are mechanically balanced, but component tests do not force each `malloc`, FFTW allocation, plan creation, or spectrum-allocation failure. The pending memory/cold stress can detect lifecycle growth and repeated-call corruption, but it is not exhaustive fault injection. This is deferred test coverage, not a defect found in the frozen source.
- **End-to-end arrays are per-call, not whole-process deadlines.** They include call-adjacent monitoring and output but exclude manifest parsing, input preload, context setup, final destruction, and summary emission. `main_phase_through_cleanup_*` and setup/summary records cover those broader costs separately.
- **Exact current-native authority is positional.** `summarize.py` treats the first requested label as the exact baseline and asserts identical identity sets for later labels. Final invocation and report text must name the raw current-native reference first; otherwise the equality statement remains mechanically valid but answers the wrong comparison question. Frozen-dense positive recovery is unaffected by label order.
- **Recall totals do not establish candidate identity.** `original_hits_recovered == original_scheduled_hits` demonstrates tolerant positive recovery under the frozen matcher. Claims that every candidate field and counter is unchanged must rely on the separate current-native exact flags, not on recall totals or projected-entry counts.
