# Genuine DS22 fitted-model consumer

`tools/ds22_fitted_models.py` consumes the completed DS22 six-proposal
initializer through its genuine reader. It does not relabel a DS22 case as
DS21 or replace another module's globals. The first intended namespace is
`local/ds22-models-v1/DS22-001`, with parent
`local/ds22-initialization-v1/DS22-001/six-proposals`.

The original fitted-c A/B/C mathematical ports, physical seed projection,
exceptional exact-compatible transfer, six receiver-lift derivations and
training selector are retained. A uses six dependent low/locked-high/final-all
paths. B and C use six starts in each of all/low/high. The maximum is 54
optimizer calls over 12 units; each fit remains capped at 20 seconds and 600
iterations with the original 25 km local radius. The existing narrowly
qualified high-stage descriptive-metadata validator remains in use. No
failed solver output becomes a stationary fit.

Model freezing first runs the genuine DS22 initializer and provider readers,
which refuse locked members. It then records an exact-byte manifest using
the unchanged `model_a_verified_manifest.py` port. This includes every
immutable predecessor stage, the provider and inventory directories, live
scientific source files, source archives, original DS22 manifest and seal,
evaluation-unit metadata, every pinned tracking-input snapshot, adapter and
causal TLE snapshot. It does not pin a mutable model output directory or another
running experiment. The helper's sole directory-inventory exclusion is derived
`development-errors*` filenames; these are never used as scientific inputs.

Runtime checks rehash the qualified files and exact directory inventories.
They retain original source/archive checks without repeatedly rediscovering
the import graph or recursively rebuilding the already qualified lineage.
Training replay calls the genuine provider's public preparation and receipt
ports and compares canonical JSON fields and evidence exactly. The original
bank loader restores the bound discovery bank and selects the frozen 46-member
candidate union. No numeric tolerance is added to source or frame comparisons.

This change addresses measured overhead: recursive DS22 parent validation grew
from 6.130 seconds at discovery to 24.792 seconds at the completed six-proposal
export. The latter completed all 18 physical exports, with maximum source
closure discrepancy 7.276e-12 Hz. Repeating that lineage walk around a fit
would unnecessarily consume the original unit budget.

Before model initialization, a durable zero-fit qualification must complete.
It measures authority checks, exact training reconstruction and post-checks;
its internal/TERM/KILL limits are 60/75/80 seconds. Failed qualification
outputs are retained and refused on retry. In the frozen v1 implementation,
a hard-killed launch-only qualification relies on the caller's no-retry rule:
the common immutable writer accepts an identical existing launch. No such
orphan or retry occurred for DS22-001. An explicit exclusive launch guard is
required before any future qualification campaign. Model
initialization retains 90/105/110 seconds; A path units retain 90/105/110;
B/C view units retain 165/175/180. Numbered clean checkpoints require explicit
scheduling; failed or orphaned units do not automatically retry. Per-unit
byte checks occur before preparation and after scientific work.

The consumer has no held-data or reference evaluation command. A final seal
requires all twelve success or explicitly finalized failure outcomes and
retains their coverage and total optimizer-call count. A separate genuine DS22
post-seal evaluation port is still needed.

These are shared-discovery baseline controls. B/C low/high views inherit the
shared bank, geographic starts and physical initialization; C also inherits
all-channel receiver lifts. A low/high stages are dependent path components.
None may be described as an independently discovered and initialized
half-band pipeline. Independent half controls remain separate required work
for the final CH1–8-versus-halves acceptance test.

Component tests build a genuine synthetic DS22 initializer chain and exercise
public training reconstruction, JSON serialization and all 54 model calls.
They enforce original fit options, all twelve sealed outcomes, cached reads
without preparation/fits, qualified-byte tamper gates, locked refusal,
failure/checkpoint retention and real short original fitter runs through A,
B and C. Component tests use synthetic data and do not launch dataset fits.
