# Conditioned moment-order NEON packing

Physical-ARM follow-up: component tests, including exact moment comparison,
passed. All candidate outputs on four dwells matched Wave3, but outer CPU rose
to 1.737549 seconds/dwell and conditioned CPU to 218.884 ms (about 193 ms in
Wave3). This single-run regression rejects the variant for speed. Full host
recovery remains 19,226/19,581 with exact candidate parity.

This bounded Wave3 experiment changes only accumulation of Taylor moments one
through four in the 41-frequency conditioned screen. Moment zero remains a
scalar FP32 sum in sample order. The existing four-frequency polynomial
evaluation, all 16 conditioned frames, exact rechecks, and final FP64 GLRT are
unchanged.

For each 32-sample block, phase-cache initialization now stores adjacent FP32
lanes containing `delta^1` through `delta^4`. Each power is generated by the
same sequential FP32 multiplication used by the original nested loop. On ARM,
the sample real and imaginary components are broadcast and accumulated across
the four order lanes with `vmul.f32` and `vadd.f32`. The host path uses four
independent scalar accumulators with the same sample order, which provides a
portable semantic check of the new layout and loop structure.

Host and sanitizer tests compare every block and all five complex moments
exactly with the original nested-loop oracle for four input patterns at all
rates. The existing end-to-end moment test retains its measured bound:
maximum absolute error 0.000854492188 and maximum screen-normalized error
0.00126164407 versus the FP64 accumulation reference. ARM was cross-compiled
only; disassembly confirms packed `vmul.f32`/`vadd.f32` instructions.

The correctly paired 704-dwell fused Wave3 host evaluation reports zero changed
windows and zero changed candidates versus `arm_wave3_combined/host704`.
Standard recovery remains 19226/19581 with 21505 unmatched positive hits.
Host timing is diagnostic because the packed path is ARM-only: conditioned time
was 12.183 ms versus 13.338 ms in the control, while fused total was 103.247 ms
versus 92.870 ms amid slower unrelated proposal and coarse stages. No ARM speed
claim is made until physical Cortex-A9 timing.
