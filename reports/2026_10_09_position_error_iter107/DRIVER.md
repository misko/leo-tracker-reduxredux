# Full193 generic recovery driver preparation

The prepared driver compares a current ordinary B7 baseline with the unchanged iteration105 generic calibration recovery for every DS16/DS17/DS18/newer-development member. No iteration107 fit or protocol freeze has run at preparation. All reserves remain closed; no RF collection or deployment is part of this experiment.

`freeze.py` validates the union of immutable105 and106 source closures, adds this iteration's source bindings/documents and new engine/controller/tests, and captures imported Python/native sources. It pins the known historical coarse-source hashes, both matched c arms,500-second slices, six slices per phase, two workers and one thread per worker. Any changed upstream source fails validation rather than receiving a silent waiver. Parent publishes the resulting protocol before workers start.

Every member runs all three current ordinary regional passes, current existing failed-coarse recovery and fresh B7 joint stages. Existing exact current stages can be read through their verified source ports; completed iteration105 endpoints are not blindly substituted. The newly authorized legacy optimization is confined to ordinary bootstrap/coarse fixed-point receipts: literal old-source/configuration gates, input/analysis/evidence/TLE/prior/score/bank identity, fixed-point/vector feasibility, saved objective agreement and current independent KKT checks all precede admission. No historical calibration, association, final, recovery or complete-region alias is permitted.

Candidate recovery enumerates every ordinary retained calibration failure across all passes/grid levels, deduplicates bound physical starts, appends recovered regions to a copy of the ordinary inventory and uses unchanged model-score selection. Calibration/association are shared; c=0 and fitted-c final/B7 budgets are matched. Reference coordinates or errors cannot choose seeds, retention, hyperparameters or operational winners.

Historical reconstruction uses the immutable85→84→82 verified protocol adapter and51 cohort loader. That historical loader compares archived horizontal-error fields only to validate immutable receipt provenance; it does not use those values to construct models, seed searches or select winners. This inherited dependency is disclosed in iteration106 `REFERENCE_DEPENDENCY_AUDIT.md`. Current evidence and observation ordering are reconstructed and hash-bound independently before source admission.

`batch.py` interleaves dataset groups in lexical member order without outcome priority, then partitions labels into two disjoint shards. Each shard runs one member/controller at a time. The parent must launch at most two shard processes; no extra concurrency infrastructure is added. `--max-members` caps the selected prefix of one shard, including already-terminal members. Each controller verifies existing terminal receipts and stops following a failed/budget-exhausted baseline, leaving the candidate explicitly not run. Failed, missing and budget-exhausted members remain in full193 report coverage.

Elapsed slice cost includes input loading and all stage/source work; phase elapsed cost sums persisted completed slices. Interrupted slices with no completion receipt have unknown durations, explicitly disclosed. Reports retain per-port source hits, legacy coarse audits/rejections, local cache hits, convergence/fallbacks and source provenance. No better in-sample score alone establishes position improvement.
