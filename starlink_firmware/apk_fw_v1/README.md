# APK firmware v1 research workspace

This directory owns the APK-derived dish firmware, reverse-engineering scripts,
tests, reports and generated results. `v1` names our first research corpus, not
a Starlink release number. The source runtime identifies a March 27, 2026 build;
see the acquisition notes and local provenance for exact package hashes.

```text
apk_fw_v1/
├── docs/                         Acquisition and firmware findings
├── reports/
│   ├── 2026_09_28_sequence_semantics/       Initial firmware and signal experiments
│   ├── 2026_09_29_firmware_cluster_reaudit/ Fresh audit and association checks
│   └── 2026_09_30_firmware_atlas/           Executable/function/callgraph atlas
└── local/                        Ignored source assets and relocation records
    └── firmware/                 APK, bundles, extracted files, original probes
```

Each report directory keeps its scripts, component tests and written findings
together. Its `local/` subdirectory holds ignored generated results, disassembly,
figures and derived signal data. DS7–DS10 source recordings and general
literature remain in their existing locations; these experiments reference them.

## Relocation and reproducibility

In the original research checkout, old report, firmware and documentation paths
are compatibility symlinks to this workspace. The Git publication retains the
previously published sequence-semantics and cluster-reaudit directories as
historical snapshots, including their existing results. Other compatibility links
point here. New work belongs in this canonical workspace. Scripts resolve the
repository root from this location; external signal-analysis inputs remain under
repo `reports/`.

The move verified SHA-256 for all 1,591 relocated files before path edits.
`local/relocation-manifest.json` preserves the original/new paths and hashes.
`local/pre-relocation-sources.tar.gz` preserves the original non-local Python
and Markdown source bytes. Historical receipts are unchanged: their method
hashes refer to those pre-relocation sources, not the path-adjusted scripts.
Do not rewrite old receipts to pretend they were generated by newer code.

Firmware, APKs and bulk results are ignored by Git. No recording or scientific
fixture was changed. The move does not change the scientific conclusions.

Run tests from the repository root (the existing firmware is needed for the
emulation assays):

```bash
OPENBLAS_NUM_THREADS=1 uv run --no-project --with numpy --with scipy --with matplotlib --with h5py --with capstone --with pyelftools --with unicorn --with pytest pytest -q starlink_firmware/apk_fw_v1/reports
```

Use each report's reproduction commands for individual experiments. Commands
using the old report paths remain valid through the compatibility links.
