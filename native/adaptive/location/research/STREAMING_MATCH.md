# Streaming Doppler candidate experiment

For the reusable module, use [location/doppler_match](../doppler_match/README.md)
and the normal location build's `leo-doppler-match` executable. The sources and
commands below are retained unchanged as the historical measured prototype;
new matcher changes belong in the module. The module does not import these
research sources.

`streaming_match.hpp` and `streaming_match_cli.cpp` implement a private,
recorded-data prototype. They stream TLE records through single-satellite orbit
buffers, apply regional visibility screening, and return per-fragment receiver
position / time-offset / satellite hypotheses. They are not a deployment default
or a public persisted contract.

Build and numerical tests:

```bash
bash tests/native_adaptive/location/research/build_streaming_match.sh host /absolute/build
/absolute/build/streaming-match OBSERVATIONS.txt CATALOGUE.tle
```

The private `SDP1` input is generated by `tools/prototype_streaming_doppler.py`
from explicitly provided measured-track and capture documents and the public
TLE archive reader. `tools/report_streaming_doppler.py` validates finalists
against direct propagation and exports candidate tuples.

The known site and published satellite choices are excluded. Splines use the
supplied training partition, and validation data are never used to choose
identities or fit frequency offsets. Training and validation are not asserted
to be independent in the statistical sense. Candidate retrieval is heuristic;
clock and position are fitted separately for each fragment. Numerical tests
cover interpolator agreement, horizon crossings and regional-edge visibility,
bounded continuous fitting, and validation-data isolation.
